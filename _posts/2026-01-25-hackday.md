Vérifions la méthode de chiffrement :

```bash
$ 7z l -slt export.zip | grep Method
Method = ZipCrypto Deflate
Method = ZipCrypto Deflate
```

**ZipCrypto** est vulnérable aux attaques know plaintext! Puisque nous avons la version en clair de `to-do_list.txt`, nous pouvons exploiter cette faiblesse.

Nous devons créer un fichier ZIP avec des **paramètres de compression identiques** :

```bash
$ zip -9 plain.zip to-do_list.txt
  adding: to-do_list.txt (deflated 36%)
```

#### Pourquoi Utiliser la Compression `-9` ?

Le flag `-9` dans zip crée le **niveau de compression maximum**. C'est crucial car :

1. **Cohérence :** Pour qu'une attaque par know plaintext fonctionne, le fichier en clair doit être compressé avec **exactement le même algorithme et les mêmes paramètres** que la version chiffrée.

2. **Niveaux de Compression ZIP :** ZIP utilise la compression DEFLATE avec des niveaux de 0 à 9 :
   - `0` = pas de compression (stockage uniquement)
   - `1-8` = différents niveaux de compression
   - `9` = compression maximum (sortie la plus petite)

3. **Pourquoi la Compression Maximum ?** Lorsque quelqu'un protège des données sensibles par mot de passe, il veut généralement :
   - Une taille de fichier plus petite pour faciliter l'exfiltration
   - La compression maximale est un choix naturel
   - Le niveau `-9` est couramment utilisé pour les archives importantes

4. **Exigences de l'Attaque :** Pour que bkcrack puisse trouver les clés de chiffrement internes, il doit comparer les octets compressés en clair avec les octets chiffrés. Utiliser un mauvais niveau de compression rendrait les données compressées différentes, cassant l'attaque.

Le flag `-9` assure la compression maximale, correspondant à ce qui a probablement été utilisé dans l'archive originale.

### 🔑 Observation

### Comprendre la Vulnérabilité

**PAP vs MSCHAPv2:**

| Protocole | Niveau de Sécurité | Description |
|----------|-------------------|-------------|
| **MSCHAPv2** | ✅ Sécurisé | Authentification challenge-response, mots de passe hashés |
| **PAP** | ❌ Vulnérable | Mot de passe seulement XORé avec MD5(secret + authenticator) |

**Pourquoi PAP est vulnérable:**
- Les mots de passe sont seulement chiffrés par XOR
- Si vous connaissez le secret partagé RADIUS, vous pouvez déchiffrer les mots de passe

### Scan Initial du PCAP

Créons un script Python pour scanner le trafic RADIUS voous pouvez directement le faire avec wireshark si vous preferez:

```python
import dpkt
import socket

with open('LAN_Traffic.pcap', 'rb') as f:
    pcap = dpkt.pcap.Reader(f)
    
    for ts, buf in pcap:
        eth = dpkt.ethernet.Ethernet(buf)
        
        if isinstance(eth.data, dpkt.ip.IP):
            ip = eth.data
            
            if isinstance(ip.data, dpkt.udp.UDP):
                udp = ip.data
                
                # RADIUS utilise les ports 1812 (auth) et 1813 (accounting)
                if udp.dport == 1812 or udp.sport == 1812:
                    print(f"Paquet RADIUS trouvé !")
                    print(f"Source: {socket.inet_ntoa(ip.src)}:{udp.sport}")
                    print(f"Dest: {socket.inet_ntoa(ip.dst)}:{udp.dport}")
```

**Résultat:** Plusieurs paquets RADIUS entre `192.168.58.254` (pfSense) et `192.168.58.101` (serveur RADIUS)

### Comprendre les Attributs RADIUS

Le protocole RADIUS utilise des **attributs** pour transporter l'information:

| Type d'Attribut | Nom | Description |
|----------------|-----|-------------|
| 1 | User-Name | Nom d'utilisateur |

while offset < len(data):

### Script pour Trouver les Connexions PAP Réussies
```python
import dpkt
import struct

requests = {}   # identifier -> détails de la requête
responses = {}  # identifier -> ACCEPT / REJECT

with open('LAN_Traffic.pcap', 'rb') as f:
    pcap = dpkt.pcap.Reader(f)

    for ts, buf in pcap:
        eth = dpkt.ethernet.Ethernet(buf)

        if not isinstance(eth.data, dpkt.ip.IP):
            continue
        ip = eth.data

        if not isinstance(ip.data, dpkt.udp.UDP):
            continue
        udp = ip.data

        if udp.dport != 1812 and udp.sport != 1812:
            continue

        data = udp.data
        if len(data) < 20:
            continue  # header RADIUS incomplet

        code = data[0]
        identifier = data[1]
        radius_len = struct.unpack("!H", data[2:4])[0]
        authenticator = data[4:20]

        # sécurité : tronquer à la longueur RADIUS annoncée
        if radius_len > len(data):
            # paquet tronqué ou capture incomplète
            continue
        data = data[:radius_len]

        # Parser les attributs
        username = None
        encrypted_pw = None
        auth_type = "Unknown"

        offset = 20
        while offset + 2 <= len(data):
            attr_type = data[offset]
            attr_len = data[offset + 1]
            if attr_len < 2 or offset + attr_len > len(data):
                break

            attr_value = data[offset + 2: offset + attr_len]

            if attr_type == 1:  # User-Name
                try:
                    username = attr_value.decode('utf-8', errors='replace')
                except Exception:
                    username = repr(attr_value)
            elif attr_type == 2:  # User-Password (PAP, chiffré RADIUS)
                encrypted_pw = attr_value
                auth_type = "PAP"
            elif attr_type == 26:  # Vendor-Specific 
                auth_type = "MS-CHAP"

            offset += attr_len

        # RADIUS codes: 1=Request, 2=Accept, 3=Reject
        if code == 1 and auth_type == "PAP":
            requests[identifier] = {
                "username": username,
                "encrypted_pw": encrypted_pw,
                "authenticator": authenticator
            }
        elif code == 2 and identifier in requests:
            responses[identifier] = "ACCEPT"
        elif code == 3 and identifier in requests:
            responses[identifier] = "REJECT"

print(f"Requêtes PAP trouvées: {len(requests)}")
print(f"Réponses associées (ACCEPT/REJECT): {len(responses)}")

# Afficher les résultats
for ident, req in requests.items():
    status = responses.get(ident, "NO_RESPONSE")
    print(f"[id={ident:3}] user={req['username']} -> {status}")


 
```

## Déchiffrement du Mot de Passe PAP

### Comprendre l'Algorithme PAP (RFC 2865)

PAP chiffre les mots de passe en utilisant cet algorithme simple:
```
1. Padding du mot de passe à un multiple de 16 octets avec des octets nuls
2. Pour le premier bloc (16 octets):
   b1 = MD5(secret + Request_Authenticator)
   c1 = p1 XOR b1
3. Pour déchiffrer:
   p1 = c1 XOR b1
```

**Représentation visuelle:**
```
Secret:        L3g4syOne!sn3o
Authenticator: dafdd437e23dd7bc8dafc4893031c2ac
                    ↓
            MD5(secret + authenticator)
                    ↓
                Hash MD5
                    ↓
    Mot de passe chiffré XOR Hash MD5
                    ↓
          Mot de passe en clair
```


### Déchiffrement 
```python
import hashlib

authenticator = bytes.fromhex('dafdd437e23dd7bc8dafc4893031c2ac')
encrypted_pw = bytes.fromhex('498817d0d24b7bc90b7ad894a63b8010')
secret = 'L3g4syOne!sn3o'  

# Déchiffrement PAP
md5_hash = hashlib.md5(secret.encode() + authenticator).digest()
decrypted = bytes(x ^ y for x, y in zip(encrypted_pw, md5_hash))

# Retirer le padding null
password = decrypted.rstrip(b'\x00').decode('utf-8')

print(f"Mot de passe: {password}")
```

### Hypothèse : Steganographie par NOP

**Steganographie NOP** : Une technique qui consiste à cacher des données dans du code en insérant stratégiquement des instructions NOP. Ces instructions :
- N'affectent **pas** le comportement du programme (elles ne font rien)
- Peuvent encoder des **bits d'information** par leur présence ou absence

---

### Identification du pattern

En analysant plus attentivement le code, j'ai remarqué que les NOPs apparaissent souvent après des instructions `add %edx,%eax` :

```nasm
; Exemple 1
add    %edx,%eax
nop              ← Bit 1 ?

; Exemple 2  
add    %edx,%eax
mov    %eax,-0x8(%rbp)  ← Pas de NOP, bit 0 ?
```

Les 35 instructions `imul` semblent délimiter des "rounds" ou blocs logiques. Chaque round contient plusieurs instructions `add`, certaines suivies de NOP, d'autres non.

---

### Script d'extraction

J'ai écrit un script Python pour automatiser l'extraction des bits :

```python
#!/usr/bin/env python3
import re
import subprocess
import sys


def extract_silence_function(binary_path):
    with open(binary_path, 'rb') as f:
        data = f.read()
    
    # Offsets de la fonction silence
    SILENCE_START = 0x1149
    SILENCE_END = 0x1feb
    silence_code = data[SILENCE_START:SILENCE_END]
    
    # Sauvegarder dans un fichier temporaire
    temp_file = "/tmp/silence.bin"
    with open(temp_file, 'wb') as f:
        f.write(silence_code)
    
    return temp_file


def disassemble_function(bin_file):
    """Désassemble avec objdump"""
    result = subprocess.check_output(
        ["objdump", "-D", "-b", "binary", "-m", "i386:x86-64", bin_file],
        text=True,
        stderr=subprocess.DEVNULL
    )
    
    instructions = []
    for line in result.splitlines():
        match = re.match(r"\s*([0-9a-f]+):\s+([0-9a-f ]+)\s+\t(.+)", line)
        if match:
            offset = int(match.group(1), 16)
            asm = match.group(3).strip()
            instructions.append((offset, asm))
    
    return instructions


def extract_bits_from_nop_pattern(instructions):
    """
    Extrait les bits en analysant les blocs délimités par 'imul'
    """
    # Trouver les positions des 'imul' (délimiteurs de rounds)
    imul_positions = [
        i for i, (_, asm) in enumerate(instructions) 
        if asm.startswith("imul")
    ]
    
    print(f"[+] {len(imul_positions)} rounds détectés")
    
    bits = []
    
    # Pour chaque round
    for round_idx in range(len(imul_positions)):
        start = 0 if round_idx == 0 else imul_positions[round_idx - 1] + 1
        end = imul_positions[round_idx] + 1
        
        round_instructions = instructions[start:end]
        
        # Analyser chaque instruction du round
        for i in range(len(round_instructions) - 1):
            current_asm = round_instructions[i][1]
            next_asm = round_instructions[i + 1][1]
            
            # Pattern clé: instructions 'add' manipulant %eax
            if current_asm.startswith("add") and "%eax" in current_asm:
                bit = 1 if next_asm == "nop" else 0
                bits.append(bit)
    
    return bits


def decode_bits_to_ascii(bits):
    """Convertit les bits en ASCII (MSB first)"""
    text = ""
    
    for i in range(0, len(bits) - 7, 8):
        byte_bits = bits[i:i+8]
        byte_value = int(''.join(map(str, byte_bits)), 2)
        
        if 32 <= byte_value < 127:
            text += chr(byte_value)
        else:
            text += f"[{byte_value:02x}]"
    
    return text


def main():
    binary_path = "eMule_Optimizer"
    
    print("="*70)
    print(" "*20 + "Wait A Bit - Solver")
    print("="*70)
    
    # Extraction
    print("\n[1] Extraction de la fonction 'silence'...")
    silence_bin = extract_silence_function(binary_path)
    
    # Désassemblage
    print("[2] Désassemblage...")
    instructions = disassemble_function(silence_bin)
    print(f"    → {len(instructions)} instructions")
    
    # Extraction des bits
    print("\n[3] Extraction des bits...")
    bits = extract_bits_from_nop_pattern(instructions)
    print(f"    → {len(bits)} bits extraits")
    print(f"    → Ones: {sum(bits)}, Zeros: {len(bits) - sum(bits)}")
    
    # Décodage
    print("\n[4] Décodage...")
    flag = decode_bits_to_ascii(bits)
    
    print(f"\n{'='*70}")
    print("FLAG TROUVÉ!")
    print("="*70)
    print(f"\n{flag}\n")


if __name__ == "__main__":
    main()
```

Le nom du challenge est **"Deep Filter"** et l'énoncé mentionne un PNG "strangely compressed". Ces deux indices pointent vers quelque chose de spécifique au format PNG : **les filtres de ligne**.

---

### Comment fonctionne la compression PNG

Le format PNG utilise un système de filtrage avant la compression zlib. Chaque **ligne** de l'image est précédée d'un **octet de filtre** qui indique comment les pixels de cette ligne sont encodés :

| Valeur | Type de filtre | Description |
|--------|---------------|-------------|
| 0 | None | Pas de filtrage |
| 1 | Sub | Différence avec le pixel de gauche |
| 2 | Up | Différence avec le pixel du dessus |
| 3 | Average | Moyenne des pixels gauche et dessus |
| 4 | Paeth | Prédicteur de Paeth |

Ces filtres optimisent la compression en réduisant la redondance des données. **Les valeurs valides sont uniquement 0 à 4.**

### Structure des données décompressées

Pour une image RGB de 250×275 pixels :
- Chaque pixel = 3 octets (R, G, B)
- Chaque ligne = 1 octet (filtre) + 250 × 3 octets (pixels) = **751 octets**
- Total = 275 lignes × 751 octets = **206 525 octets**

---

### Extraction et analyse des filtres

J'ai écrit un script Python pour extraire et analyser les filter bytes :

```python
import zlib
import struct

with open('logo.png', 'rb') as f:
    data = f.read()

# Parser les chunks PNG pour extraire IDAT
pos = 8  # Skip PNG signature (89 50 4E 47 0D 0A 1A 0A)
idat_data = b''

while pos < len(data):
    length = struct.unpack('>I', data[pos:pos+4])[0]
    chunk_type = data[pos+4:pos+8]
    
    if chunk_type == b'IDAT':
        idat_data += data[pos+8:pos+8+length]
    
    pos += 12 + length  # 4 (length) + 4 (type) + length + 4 (CRC)

# Décompresser les données
decompressed = zlib.decompress(idat_data)
print(f"Taille décompressée : {len(decompressed)} octets")

# Paramètres de l'image
width, height = 250, 275
row_size = 1 + width * 3  # 751 octets par ligne

# Extraire le filter byte de chaque ligne
filter_bytes = []
for row in range(height):
    filter_byte = decompressed[row * row_size]
    filter_bytes.append(filter_byte)

# Analyser les valeurs
print(f"Valeurs uniques : {set(filter_bytes)}")
print(f"Premiers filtres : {filter_bytes[:50]}")
```

 Les filtres ne prennent que deux valeurs : **1 et 2**. C'est  suspect ! 

Normalement, un encodeur PNG choisit le filtre optimal pour chaque ligne (celui qui donne la meilleure compression). Avoir uniquement des 1 et des 2 sur 275 lignes es improbable... sauf si c'est volontaire.

---

### Hypothèse : encodage binaire

Avec seulement deux valeurs possibles, l'hypothèse la plus évidente est un **encodage binaire** :
- Filtre **1** → bit **0**
- Filtre **2** → bit **1**

### Script de décodage

```python
import zlib
import struct

with open('logo.png', 'rb') as f:
    data = f.read()

# Extraction des données IDAT
pos = 8
idat_data = b''
while pos < len(data):
    length = struct.unpack('>I', data[pos:pos+4])[0]
    chunk_type = data[pos+4:pos+8]
    if chunk_type == b'IDAT':
        idat_data += data[pos+8:pos+8+length]
    pos += 12 + length

# Décompression
decompressed = zlib.decompress(idat_data)

# Paramètres
width, height = 250, 275
row_size = 1 + width * 3

# Extraction des filter bytes
filter_bytes = [decompressed[row * row_size] for row in range(height)]

# Conversion en binaire : 1 -> '0', 2 -> '1'
binary_string = ''.join('0' if b == 1 else '1' for b in filter_bytes)
print(f"Binaire : {binary_string[:64]}...")

# Conversion binaire -> ASCII
flag = ''
for i in range(0, len(binary_string) - 7, 8):
    byte_value = int(binary_string[i:i+8], 2)
    if byte_value > 0:  # Ignorer les null bytes
        flag += chr(byte_value)

print(f"Flag : {flag}")
```

### Étape 1 : Extraction des LSB du canal rouge

La première étape consiste à parcourir chaque pixel de l'image et extraire le bit de poids faible (LSB) du canal rouge.

```python
from PIL import Image

def extract_lsb_red(image_path):
    """
    Extrait les bits de poids faible du canal rouge de l'image
    """
    img = Image.open(image_path)
    pixels = img.load()
    width, height = img.size
    
    bits = []
    
    # Parcourir tous les pixels
    for y in range(height):
        for x in range(width):
            # Récupérer le pixel (R, G, B) ou (R, G, B, A)
            pixel = pixels[x, y]
            red_channel = pixel[0]
            
            # Extraire le bit de poids faible
            lsb = red_channel & 1
            bits.append(str(lsb))
    
    return ''.join(bits)
```

### Étape 2 : Regroupement en octets

Une fois les bits extraits, on les regroupe par 8 pour reformer des bytes :

```python
def bits_to_bytes(bits_string):

    bytes_list = []
    
    # Traiter les bits par groupes de 8
    for i in range(0, len(bits_string), 8):
        byte_bits = bits_string[i:i+8]
        
        # S'assurer d'avoir 8 bits
        if len(byte_bits) == 8:
            # Convertir les bits en entier
            byte_value = int(byte_bits, 2)
            bytes_list.append(byte_value)
    
    return bytes(bytes_list)
```

### Étape 3 : Déchiffrement XOR avec la clé 42

Le message extrait est encore chiffré. La référence à "The Ultimate Question" nous donne la clé : **42** (0x2A en hexadécimal).

```python
def xor_decrypt(data, key):
    """
    Déchiffre les données avec XOR et une clé
    """
    decrypted = []
    
    for byte in data:
        # XOR avec la clé
        decrypted_byte = byte ^ key
        decrypted.append(decrypted_byte)
    
    return bytes(decrypted)
```
